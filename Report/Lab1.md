# การพิสูจน์รูปร่าง (Bit-to-Pixel Forensic Reconstruction)

บนหน้าจอ OLED มาตรฐาน (เช่น SSD1306) ข้อมูล 1 Byte จะถูกวาดในแนวตั้ง (8 พิกเซล) โดยที่ Bit 0 อยู่ด้านบนสุด (Top) และ Bit 7 อยู่ด้านล่างสุด (Bottom) ของแถวนั้นๆ

เมื่อนำข้อมูลของคอลัมน์ 30 ถึง 34 (กลุ่มข้อมูลแรก) มาพล็อตกราฟฟิกพิกเซล (■ = 1, □ = 0) จะได้ผลลัพธ์ดังนี้:

## พิกเซลคอลัมน์ 30 - 34

```plaintext
Bit 0 (Top):    □ □ □ □ □
Bit 1:          □ □ □ □ □
Bit 2:          □ □ □ □ □
Bit 3:          □ □ □ □ □
Bit 4:          ■ □ □ □ ■  <-- ขาตั้งด้านซ้ายและขวา
Bit 5:          ■ □ □ □ ■
Bit 6:          ■ □ □ □ ■
Bit 7 (Bottom): ■ ■ ■ ■ ■  <-- เส้นแกนขวางตรงกลางของตัว H
```

# บทสรุปการพิสูจน์:

รูปแบบของบิตที่ปรากฏ ไม่ได้สร้างเป็นตัวอักษร 'H' ที่สมบูรณ์ในบรรทัดนี้ แต่เป็น "ครึ่งบน" ของตัวอักษร 'H'

หลักฐานชี้ให้เห็นว่าระบบกำลังเรนเดอร์ตัวอักษรที่มีขนาดใหญ่กว่า 8 พิกเซล (Font ขนาดใหญ่) ซึ่งต้องใช้หน่วยความจำหน้าจอหลาย Page ต่อกัน โดย Page ปัจจุบัน (ที่ Dump ออกมา) เก็บเฉพาะส่วนครึ่งบนของตัวอักษร (ขาด้านบน 2 ข้าง และเส้นขวางตรงกลาง) ส่วนขาด้านล่างของตัว 'H' จะถูกวาดอยู่ใน Page ถัดไปของหน่วยความจำหน้าจอ (นอกจากนี้คอลัมน์ 36-40 ยังเป็นภาพตัดครึ่งบนของตัวอักษร 'e' อีกด้วย)

## 5. คำถามท้ายการทดลองเพื่อการประเมินผล (Review Questions)
1. จากการทำ Hex Dump ในกิจกรรมนิติวิทยาศาสตร์ จงอธิบายว่าทำไมตัวอักษร `'H'` จึงใช้ข้อมูลจำนวน 5 ไบต์ และแต่ละไบต์ทำหน้าที่ควบคุมพิกเซลในทิศทางใด?
```
จอ SSD1306 จัดการหน่วยความจำเป็นแบบ "Page"  1 Page จะมีความสูง 8 พิกเซล ซึ่ง 8 พิกเซลนี้ถูกรวบเก็บไว้ใน "1 ไบต์" พอดี ฟอนต์ของเราเป็นขนาด 5x7 หมายความว่ามันมีความกว้าง 5 คอลัมน์ ดังนั้น 1 คอลัมน์ = 1 ไบต์ กว้าง 5 คอลัมน์ จึงใช้ 5 ไบต์เรียงต่อกันในแนวนอน
```

2. หากเราสลับสายไฟระหว่างขา **D0** และ **D1** จะเกิดผลอย่างไรกับสัญญาณ SPI และหน้าจอจะติดหรือไม่?
```
บัส SPI สื่อสารแบบซิงโครนัส ขา SCK ทำหน้าที่ส่งจังหวะนาฬิกา ส่วน MOSI ส่งข้อมูลพิกเซล ถ้าสลับกัน ชิปจอจะเอาสัญญาณข้อมูลไปตีความว่าเป็นจังหวะนาฬิกา และเอาจังหวะนาฬิกาไปตีความเป็นพิกเซล ทำให้คุยกันไม่รู้เรื่อง  ส่งผลให้หน้าจอมืดสนิท หรืออาจมีจุดสุ่มๆ ขึ้นแบบเละเทะ
```

3. เหตุใดการแก้ไขพิกัด $(x, y)$ บน `s_oled_buffer` จึงไม่ทำให้ภาพบนหน้าจอจริงเปลี่ยนทันที จนกว่าจะมีการเรียกคำสั่ง `oled_flush()`?
```
เพราะสถาปัตยกรรมนี้เราใช้เทคนิค Double Buffering ตัวแปร s_oled_buffer เป็นเพียงพื้นที่ RAM ในฝั่งไมโครคอนโทรลเลอร์ เราแค่วาดรูปทดไว้ในกระดาษร่างของเราก่อน ทำให้เราวาด/ลบกี่พันครั้งก็ได้โดยที่จอไม่กระพริบ เมื่อภาพเสร็จสมบูรณ์ คำสั่ง oled_flush() ถึงจะทำการเหมาส่งข้อมูล 1,024 ไบต์ ผ่านสาย SPI ไปอัปเดตที่ RAM ของชิปจอ แบบรวดเดียว ภาพถึงจะปรากฏขึ้นพร้อมกันครับ
```
